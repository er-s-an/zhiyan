# Gate A：V2.1 数据契约与一页样例人工验收

> 验收对象：`lib/v2/briefs/main-case.json`、`docs/v2.1/main-case-decision-brief.html`、`docs/v2.1/evidence-map.md`
> 验收方式：真实主案例证据对照 + 一人阅读测试（本机浏览器）；外部 3–5 人测试记录见 `user-test-script.md`，尚未执行，不得伪造。

## 1. 数据契约

- [x] `InitialBelief` 在检索前捕获，字段包括决策问题、产品想法、目标用户、假设、担心、`capturedAt`、计划版本。
- [x] `BeliefUpdate` 最多 3 条，字段包括原始假设、新理解、变化类型、证据 ID、反例 ID、产品影响、下一步、状态。
- [x] `OpportunityHypothesis` 最多 3 张，字段包含人群/场景/问题/替代方案/为什么不够/产品方向/预期结果/证伪条件/证据/反例/证据强度/未知项/下一步验证。
- [x] `RoundSnapshot` 三轮，包含目的、查询 ID、新词、认知变化、覆盖变化、下一轮原因、停止原因。
- [x] `StopReason` 区分 `budget_exhausted / saturation / no_results / error`；主案例为 `budget_exhausted`，文案明确「不宣称主题饱和」。
- [x] `DecisionBrief` 包含建议、为什么不直接开发、先验证什么、不做什么、产品选项、下一步验证、未回答问题和证据边界。

## 2. 真实证据对照

- [x] 2 张机会卡：验收—尾款工作流（强）、创作者交付物控制（中）。
- [x] 不强行凑第三张；未形成第三机会时明确写出证据不足。
- [x] 每条支持/反例都来自 `lib/v2/demos/main-case.json` 的纳入样本；证据映射见 `evidence-map.md`。
- [x] 原始想法在检索前捕获；`capturedAt` 不晚于研究确认时间。
- [x] 没有无来源数字、市场规模、购买率或付费意愿结论。
- [x] 直接表达、多样本归纳、AI 推断在字段和文案中分开。

## 3. 一页样例阅读测试（本机）

打开 `main-case-decision-brief.html`，在 2 分钟内回答：

- 原来的想法是什么？→ 做 AI 合同与回款工具，面向所有中国自由职业者。
- 讨论改变了什么？→ 核心不是合同文本，而是验收、范围变更、交付物控制和尾款；人群至少分成程序员/外包和插画/约稿两类。
- 最值得验证的机会？→ 验收—尾款工作流；其次创作者交付物控制。
- 现在该做什么？→ 5 个访谈 + 两版价值主张落地页；不直接开发完整合同工具。
- 哪一步还不能证明？→ 付费意愿、人群优先级、平台外迁移、反例是否足够。

本机自测结论：**信息层级可以通过 Gate A**；仍需外部 3–5 人复测，不能把本机自测当作用户验证。
