# 专业产品与市场调研：实践全景与知研台差距评估

> 评估对象：知研台当前实现（`er-s-an/zhiyan`，2026-11-11）
> 评估方法：专业框架/行业标准对照 + 代码审计 + 四个示例研究的样本统计
> 结论口径：既看「专业上应该怎么做」，也看「知研台实际做到了哪一步」；不把「方法边界」误判为「产品缺陷」。

---

## 0. 结论先行

专业的产品与市场调研，核心不是「找到更多资料」，而是**用可辩护的证据，降低一个具体决策的不确定性**。完整链路是：

> 决策问题 → 研究问题/假设 → 方法组合 → 抽样与数据 → 分析 → 洞察 → 建议 → 决策与复盘

按这条链路对照，知研台的现状是：

- **骨架是对的，肌肉还不够。** 已经做到决策先行、研究协议、确认门、样本可追溯、编码透明、边界锁定、交付可导出；在「知乎 UGC 的二手定性发现」这一窄切片上，是一个**方法诚实、可演示、可审计**的原型。
- **但它目前只能支持早期需求探索/假设生成**，不能支持市场规模、细分、定价、购买意愿、品牌定位、竞争格局或 B2B 采购决策。把产品讲成「产品与市场研究平台」会超出证据能力；讲成「面向产研团队的公开社区证据工作台」更准确。
- **成熟度评分：约 2.4 / 5**（按完整产品/市场研究能力加权）；如果只按「知乎 UGC 二手定性研究」这个窄目标，约 **2.9 / 5**。专业团队通常要求 4 / 5 以上才敢把结论带进决策会。
- **最大优势**：确认门 + 样本溯源 + 确定性投影 + 锁定边界。这四点比大多数「AI 一键生成调研报告」产品更专业。
- **最大短板**：单平台、非概率抽样、关键词编码停在「计数」层、没有三角验证、没有量化/市场模型、没有研究资产库与协作、没有 AAPOR 级的方法披露。

一句话：**知研台现在是一个很好的「证据工作台起点」，还不是一个完整的「产品与市场研究系统」。**

## 1. 专业人士怎么想：六个心智模型

### 1.1 决策导向，而不是数据导向

专业研究的起点不是「去搜一下」，而是「谁要在什么时间、基于什么标准、做什么决定」。Marty Cagan 把产品风险拆成四类：**价值风险、可用性风险、可行性风险、商业可行性风险**；研究设计要先对准其中真正要降低的那一类风险，而不是平均用力。[1]

知研台已经有「这次研究要支持什么决策」这一字段，这是明显优于普通搜索工具的地方；但还缺**决策人、截止时间、决策标准、不做什么的边界**。没有这些，「决策」仍然是一句抽象描述。

### 1.2 问题树与假设驱动

专业团队会把模糊问题拆成 MECE 的问题树：先写研究问题（RQ），再写可被推翻的假设，再决定用什么证据验证。研究不是「收集支持自己的材料」，而是主动寻找**反证**和**边界条件**。

知研台目前有「场景 + 能回答/不能回答 + 停止规则」，已经接近研究设计；但没有显式的 `ResearchQuestion[]`、`Hypothesis[]`、`Assumption[]`，也没有「什么结果会让我们改变结论」的反证设计。

### 1.3 证据分级与三角验证

NN/g 的方法地图把研究分成三个维度：**态度 vs 行为、定性 vs 定量、使用情境**；并明确指出「几乎所有的项目都需要多种方法，并把不同来源的洞察结合起来」。[2]

专业研究不会把单一平台的高赞帖子当成市场事实，而会做三角验证：一手访谈 + 问卷 + 行为数据 + 二手行业报告 + 内部数据，至少两个独立来源指向同一结论，才提高置信度。知研台目前是**单平台、单方法、单时点**，这是它最大的方法论缺口。

### 1.4 方法必须匹配问题

专业研究先问「这个问题应该用什么方法回答」，而不是「我手上有什么工具」。例如：

- 问「为什么用户不用」→ 深访、情境访谈、可用性测试；
- 问「有多少人、愿意付多少」→ 问卷、MaxDiff、联合分析、价格测试；
- 问「市场多大」→ TAM/SAM/SOM、自下而上建模、行业报告；
- 问「竞品在做什么」→ 竞争情报、定价拆解、win/loss；
- 问「早期机会在哪」→ UGC/社区观察、JTBD 访谈、日记法。

知研台目前只有一种方法：**知乎公开内容的检索 + 关键词编码**。它适合「早期机会/语言/失败模式」，不适合上述其他问题。

### 1.5 研究是社会过程，不是一份文档

专业研究要处理利益相关者：谁赞助、谁决策、谁反对、什么时间要、结论要多细。Teresa Torres 的机会解决方案树强调：从业务结果出发，映射机会空间，再选择目标机会、生成多个方案、拆解假设、做假设测试；研究要持续进行，而不是一次性报告。[3]

知研台目前是「单用户 + 本地浏览器 + 一份报告」，缺 stakeholder、评审、评论、决策记录和结果追踪。对个人快速研究够用，对团队协作不够。

### 1.6 伦理、可复现与 AI 披露

AAPOR 的道德与披露标准要求：披露数据收集策略、研究赞助方/执行方、测量工具、研究总体、抽样与招募方法、数据收集方式与日期、样本量与精度说明、加权方式、数据处理与质检、局限性，以及 AI 在数据收集/处理中的用途与人工监督方式；内容分析还要报告编码人数、编码者间信度，以及自动编码所用软件/规则。[4]

知研台有「样本可追溯、编码规则可见、AI 只做翻译」的好基础，但还没有一份面向评审的**方法披露块**，也没有 PII/平台条款/内容使用边界的正式说明。

## 2. 专业人士怎么做：一条完整工作流

| 阶段 | 专业动作 | 关键产出 | 知研台现状 |
|---|---|---|---|
| 1. 立项 | 明确决策、决策人、截止时间、约束、成功标准、伦理审查 | Research brief / 研究章程 | 有「决策」和简报；缺决策人、时间、标准、伦理 |
| 2. 设计 | 研究问题、假设、方法选择、抽样计划、分析计划、交付计划 | Research plan / 讨论指南 / 问卷 | 有协议、场景、查询、停止规则；缺 RQ/假设、方法选择理由、抽样计划、分析计划 |
| 3. 收集 | 一手：访谈、问卷、可用性、田野；二手：桌面研究、行业报告、内部数据；UGC：社媒/社区 | 原始数据 + 数据字典 | 只有知乎搜索/热榜/直答；无一手、无内部数据、无跨平台 |
| 4. 分析 | 定性编码/主题分析、亲和图、三角验证；定量统计、细分、联合分析、价格测试 | 编码本、主题、模型、洞察 | 关键词编码 + 计数 + 覆盖/冲突/过时标记；无主题归纳、无负案例、无信度、无统计模型 |
| 5. 综合 | 洞察 → 含义 → 建议；优先级、置信度、风险、下一步实验 | 决策备忘录、机会树、路线图输入 | 有发现（计数陈述）、边界、下一步方法；缺「含义/建议/优先级/置信度」 |
| 6. 交付与复盘 | 评审会、决策记录、研究资产库、结果追踪 | 决策 log、repo、复盘 | 有报告导出；无团队协作、资产库、决策追踪 |

这张表说明：知研台把第 1–2 步的「方法协议」做得不错，第 3–4 步只覆盖了公开 UGC 的一小类，第 5–6 步明显偏薄。

## 3. 数据源全景：专业团队会看什么

专业团队通常会组合一手、二手、内部与外部数据，而不是只用一个平台（[11][12]）。

| 类别 | 典型来源 | 能回答的问题 | 主要偏差/限制 |
|---|---|---|---|
| 一手定性 | 深度访谈、JTBD/switch 访谈、情境访谈、焦点小组、日记法、可用性测试 | 为什么、如何、决策过程、未被满足的需求 | 样本小、招募偏差、访谈者偏差、不可统计外推 |
| 一手定量 | 问卷、MaxDiff、联合分析（conjoint）、Van Westendorp 价格测试、Kano、A/B 实验 | 有多少、哪些属性重要、价格敏感度、优先级 | 设计偏差、自报偏差、样本代表性、成本高 |
| 内部行为数据 | 产品分析、CRM、客服工单、销售通话、NPS、流失/续费、win/loss | 真实行为、留存/流失、购买路径 | 口径、埋点质量、隐私、部门墙 |
| 二手行业 | Gartner/Forrester/IDC、艾瑞（[15]）、QuestMobile（[14]）、券商/财报、招股书、专利、招聘、应用商店 | 市场规模、竞争格局、趋势、组织能力 | 报告口径、时效、价格、二手转述 |
| 社媒/UGC | 知乎、小红书、抖音、B 站、微博、Reddit、Amazon reviews、App Store、垂直论坛 | 语言、场景、痛点、反对意见、口碑 | 平台人群偏差、算法排序、营销/水军、不可外推 |
| 搜索/趋势 | 百度指数、微信指数、Google Trends、巨量算数（[17]）、新榜（[16]） | 需求热度、季节/趋势、内容供给 | 指数不等于销量；关键词覆盖有限 |
| 专家/渠道 | 专家网络、经销商、展会、KOL、前员工 | 行业 know-how、渠道现实、竞争动态 | 合规、样本少、主观性强 |
| 实验/市场 | 落地页、预售、众筹、A/B、区域试点 | 真实转化、价格弹性、需求强度 | 成本、伦理、外部效度 |

这张表可以直接变成知研台的「数据源路线图」：现在只占「社媒/UGC」中的知乎一格。

## 4. 方法选择矩阵：什么问题用什么方法

| 研究问题 | 首选方法 | 次选/补充 | 知研台能否回答 |
|---|---|---|---|
| 用户有哪些未被满足的需求？ | 深访、JTBD、日记法、UGC 分析 | 问卷、客服工单 | **部分**（仅知乎公开表达） |
| 哪些功能是刚需/伪需求？ | 访谈 + 概念测试 + MaxDiff | UGC 编码、竞品评论 | **部分**（关键词编码，非需求优先级） |
| 市场有多大？ | TAM/SAM/SOM、自下而上建模、行业报告 | 财报、渠道数据 | **不能** |
| 该服务哪个细分？ | 细分研究、聚类、态度/行为数据 | 深访、销售数据 | **不能**（只能从场景粗略分组） |
| 用户愿意付多少？ | Van Westendorp、联合分析、价格测试 | 竞品定价、预售 | **不能**（且被锁定边界排除） |
| 哪个概念更有吸引力？ | 概念测试、联合分析、A/B | 访谈、落地页 | **不能**（只能生成假设） |
| 竞品在做什么？ | 竞争情报、定价拆解、win/loss、专利/招聘 | UGC 提及分析 | **很弱**（没有竞品集/对标） |
| 为什么赢/输单？ | win/loss 访谈、CRM、销售复盘 | 客户访谈 | **不能**（B2B 数据不在范围内） |
| 品牌/定位是否成立？ | 感知地图、品牌追踪、社媒聆听 | 深访、内容分析 | **很弱**（只有话题/措辞，不是品牌资产） |
| 可用性有没有问题？ | 可用性测试、行为分析 | 客服、访谈 | **不能** |
| 内容/传播是否有效？ | 社媒聆听、A/B、投放数据、新榜/QuestMobile | UGC 分析 | **很弱**（只有知乎文本） |
| 出海市场是否成立？ | 目标市场一手/二手、当地 reviews、渠道/合规 | 专家、竞品 | **不能**（用中文知乎推断北美，来源与市场不匹配） |

这张表是「广度」的核心：知研台只覆盖了其中 2–3 行的一部分。

## 5. 专业质量门槛：不是「看起来像报告」就够了

### 5.1 抽样与推断

- 概率样本才能谈抽样误差；非概率样本必须明确说明「不能计算误差、不能外推」。
- 内容分析要说明：分析单位（帖子/回答/评论）、抽样框、纳入/排除规则、时间范围、是否普查、编码人数与信度。[4]
- 定性研究常用「信息饱和/信息力量」而不是固定样本量；需要说明何时停止、为什么停止。
- 专业团队会做**敏感性分析**：把过时、营销、重复、单一来源的条目拿掉后，结论是否还成立。

知研台现状：固定每条查询 5 条、共 4 条查询（示例中约 20 条），按搜索排序取前几条；没有抽样框、没有配额、没有饱和判断、没有敏感性分析；结果是「本样本计数」，且示例中确实包含 2019/2021/2022 年的帖子和营销帖，仍计入发现。质量视图只做标记，不做剔除或稳健性检验。

### 5.2 定性分析

Braun & Clarke 的主题分析强调：熟悉数据 → 生成编码 → 形成主题 → 复核主题 → 定义命名 → 写作；同时区分「编码信度取向」和「反身性取向」，前者需要多编码者与 Cohen's kappa，后者需要反身性日志；主题不是「关键词出现次数」，而是围绕核心概念的共同意义。[5]

知研台现状：编码本是**预先写好的关键词规则**，属于演绎式、内容分析式编码；这本身没有错，但它只能回答「哪些词出现了」，不能自动回答「这意味着什么」。示例中平均每条纳入条目命中 2.7–5.2 个编码（户外案例 5.2），说明关键词编码的区分度有限；没有否定/反讽/条件句处理，也没有人工双编码与信度。

### 5.3 量化与市场模型

- TAM/SAM/SOM 需要自上而下（行业报告）与自下而上（客户数 × 客单价 × 渗透率）交叉验证。[6]
- 联合分析（conjoint）通过让受访者在属性组合中做选择，估计属性效用与市场份额，适合定价/功能组合；但设计复杂、样本要求高。[7]
- 细分需要先定义细分基础（需求/行为/态度/人口），再做统计聚类或先验分组，最后评估规模、增长、竞争强度与公司匹配度。[8]
- Kano 模型把功能分为必备/期望/魅力/无差异/反向，用来讨论功能优先级；它需要专门问卷，不是关键词分析能替代的。[20]
- 价格研究常用 Van Westendorp、Gabor-Granger、MaxDiff（[19]）、联合分析；不同方法回答不同问题，不能互相替代。

知研台现状：完全没有这些能力，且明确把「购买意愿/宣称验证」锁在方法外。对「UGC 发现」这是诚实；对「市场研究」这是缺能力。

### 5.4 竞争情报与 B2B

竞争情报是「对外部竞争环境进行定义、收集、分析、分发」的协调过程，强调多源、合法、可行动；不是看几篇竞品软文。[9]
B2B 还要处理：采购委员会（经济买家、技术买家、使用者、把关者）、账户分层、win/loss、销售周期、合同/合规。公开知乎帖子通常只能代表个人表达，不能代表企业采购决策。

知研台现状：没有竞品集、没有账户/角色、没有 win/loss、没有内部销售数据；B2B 场景（AI 会议纪要）用知乎个人帖子推断团队采购，这是**来源与决策单位不匹配**。

### 5.5 AI 与自动化质量

Teresa Torres 的 AI evals 实践强调：先做错误分析，定义「好」的标准；能用确定性代码断言就用代码；需要语义判断才用 LLM-as-judge；要有 golden dataset、baseline、实验变体与回归测试；不要把「什么算好」外包给模型或供应商。[10]

知研台现状：LLM 只做翻译，不参与发现，这是很好的风险控制；但翻译质量没有 eval、没有人工抽检、没有「引用是否忠实」的断言；编码规则是确定性的，但没有对编码准确率的评估（例如随机抽样人工复核、与人工编码对比）。

### 5.6 伦理、隐私与内容使用

AAPOR 要求保护参与者隐私、披露 AI 使用、区分人类回答与 AI 生成回答；内容分析要说明来源、单位、抽样、编码与 AI 参与方式。[4]
ICC/ESOMAR 行为准则同样是行业底线（同意、透明、数据最小化、不得误导）。[18]

知研台现状：使用公开知乎内容并保留原链接，这是合理起点；但没有 PII 处理策略、没有平台条款/内容使用说明、没有作者匿名化选项、没有保留期限、没有 AI 使用披露。作为个人原型可以接受，作为团队产品是 blocker。

## 6. 知研台做对了什么（不要丢掉）

1. **决策先行**：不是搜索词，而是「决策 → 研究设计」。这是专业研究最稀缺的产品化能力。
2. **确认门**：设计未确认前不调用知乎；服务端每次检索重新校验设计；设计外查询拒绝。这解决了「AI 直接给结论」的信任问题。
3. **样本是唯一事实源**：分析、质检、报告都是投影；排除/恢复/改标签后重算。专业研究最怕「报告和原始数据对不上」，这一点做对了。
4. **每条来源可解释**：为什么纳入、来自哪条查询、时间、场景、营销/重复/二手标记、编码。这是可审计性的基础。
5. **锁定边界**：「现有知乎讨论不能证明购买意愿」「不能把一条宣称验证成足以支撑购买」。很多 AI 调研产品缺的正是这个。
6. **确定性编码 + LLM 只翻译**：发现、计数、边界由代码写，模型不碰结论。这在 AI 产品里是加分项。
7. **诚实交付**：质检页首屏就是「可以支持/不能证明」，交付页带边界与下一步方法。
8. **工程可验证**：领域测试、确认门测试、示例快照、构建与浏览器端到端验证。

这些是「专业感」的来源，也是后续扩展的地基。

## 7. 逐项对照评分

评分说明：1 = 缺失/临时；2 = 有雏形但不可靠；3 = 有定义、可用于窄场景；4 = 接近专业级；5 = 行业最佳实践/可审计。权重按「完整产品与市场研究」价值分配。

| 维度 | 权重 | 得分 | 现状证据 | 主要差距 |
|---|---:|---:|---|---|
| 决策 framing 与利益相关者 | 12% | 4.0 | 决策字段、简报、阶段、边界 | 无决策人/截止/标准/成功指标 |
| 研究问题/假设/风险 | 10% | 2.0 | 场景、能回答/不能回答、停止规则 | 无 RQ、假设、assumption、四类风险映射 |
| 方法匹配与设计 | 12% | 2.5 | 一种方法（知乎 UGC + 关键词编码） | 无方法库/选择理由/多方法设计 |
| 抽样与数据收集 | 12% | 1.5 | 4 条查询 × 5 条，固定停止 | 无抽样框、配额、饱和、敏感性分析 |
| 数据源广度与三角验证 | 12% | 1.5 | 知乎搜索/热榜/直答；示例热榜 0 贡献 | 单平台、无内部/市场/竞品/海外数据 |
| 分析深度与严谨性 | 12% | 2.5 | 可见编码本、计数、覆盖/冲突/过时 | 无主题归纳、负案例、双编码/信度、反身性 |
| 量化/市场/定价 | 10% | 0.5 | 明确不做购买意愿 | 无问卷、细分、TAM/SAM/SOM、conjoint、价格测试 |
| 竞争/B2B 情报 | 6% | 0.5 | 无 | 无竞品集、win/loss、采购委员会、账户数据 |
| 质量/伦理/AI 披露 | 8% | 2.5 | 样本标记、锁定边界、LLM 仅翻译 | 无 AAPOR 式披露、PII/同意/保留、AI 使用声明 |
| 洞察/建议/决策支持 | 8% | 2.0 | 发现 + 边界 + 下一步方法 | 发现是计数陈述；无含义/建议/优先级/置信度 |

如果只按「知乎 UGC 二手定性发现」这个窄目标重新加权，约 **2.9 / 5**：方法诚实、产品可用，但分析深度、抽样与洞察仍不足。

## 8. 十个关键差距（按影响排序）

### 差距 1：研究问题/假设/风险没有显式化

**专业做法**：每个研究先写 3–6 个 RQ、每个 RQ 对应的假设与反证条件；用 Cagan 四类风险标注「这份研究降低哪类风险、不降低哪类」。
**知研台**：有决策、场景、能/不能回答，但没有 RQ/假设/风险矩阵。
**影响**：研究容易变成「把场景都搜一遍」，而不是「验证一个可能改变决策的判断」。

### 差距 2：单平台、非概率、Top-N 抽样

**专业做法**：定义总体、抽样框、纳入/排除、配额、饱和标准；非概率样本明确不外推；做敏感性分析。
**知研台**：每条查询取前 5 条，固定 4 条查询；示例中 20 条全部来自知乎搜索；热榜扫描 30 条、纳入 0 条；无配额/饱和/敏感性分析。
**影响**：样本是「搜索排序的便利样本」，不是「研究总体」；结论只能用于假设生成。

### 差距 3：分析停在「关键词计数」，没有到「洞察」

**专业做法**：编码 → 主题 → 解释 → 含义 → 建议；主题要回答「这对决策意味着什么」，而不是「多少条提到」。
**知研台**：发现文本是「N 条纳入条目带有 X，日期从 A 到 B」，本质是编码计数；没有解释层、建议层、优先级、置信度。
**影响**：报告可以读，但不能直接支持「做/不做、先做哪个、怎么定位」的决策。

### 差距 4：没有量化与市场模型

**专业做法**：TAM/SAM/SOM、细分、MaxDiff/conjoint、价格测试、问卷与实验。
**知研台**：明确排除购买意愿/宣称验证，这是诚实；但也因此不能回答市场大小、价格、优先级、份额。
**影响**：适合早期发现，不适合立项/定价/市场进入决策。

### 差距 5：没有竞争情报与 B2B 决策单元

**专业做法**：竞品集、定价/功能拆解、win/loss、采购委员会、账户分层、内部销售/CRM。
**知研台**：没有竞品模型，也没有 B2B 决策单元；B2B 示例用个人发帖推断团队采购。
**影响**：B2B/出海场景的证据与决策单位不匹配。

### 差距 6：数据源与市场不匹配（尤其出海）

**专业做法**：研究北美市场，应使用北美用户/渠道/评论/法规数据；用中文知乎只能研究中文用户或中国卖家的认知。
**知研台**：户外储能示例用知乎中文讨论推断北美需求。
**影响**：结论可能方向对、细节错；专业评审会直接质疑外部效度。

### 差距 7：没有饱和、信度、负案例与稳健性检验

**专业做法**：说明何时停止、双编码/信度、主动找反例、去掉营销/过时/单一来源后结论是否稳定。
**知研台**：固定样本量；单编码者（规则）；示例中营销帖和 2019/2021 年帖子仍计入发现；质量标记不参与剔除/敏感性分析。
**影响**：计数可能被营销、旧帖、顺带提及放大；「发现」的稳健性未知。

### 差距 8：没有研究资产库、协作与治理

**专业做法**：ResearchOps：研究仓库、标签/检索、权限、保留期限、复用、评论/评审、审计。[13]
**知研台**：localStorage + 静态 JSON；无团队、无权限、无评论、无历史版本。
**影响**：个人可用，团队不可运营；研究无法沉淀为组织资产。

### 差距 9：没有 AAPOR 级方法披露与 AI 披露

**专业做法**：披露数据收集、总体、抽样、日期、样本量/精度、编码与信度、局限性、AI 用途与人工监督。
**知研台**：有「本样本」与边界，但没有完整披露块；没有 AI 使用声明（虽然实际只有翻译）。
**影响**：专业评审无法独立判断证据强度；也不利于建立信任。

### 差距 10：没有决策闭环

**专业做法**：决策 log、建议与置信度、谁采纳了什么、后续是否验证、结果追踪。
**知研台**：交付报告即结束；没有决策记录与结果反馈。
**影响**：研究无法证明自己的价值，也无法从决策结果中学习。

## 9. 示例数据审计：用事实说话

四个示例均由真实知乎检索生成（`lib/demos/*.json`），以下统计能说明「已达到」与「未达到」：

| 指标 | 喂食器 | AI 会议纪要 | 户外储能 | AI 知识库 |
|---|---:|---:|---:|---:|
| 样本条目 | 20 | 20 | 20 | 20 |
| 纳入 | 18 | 19 | 18 | 19 |
| 发现（编码计数） | 6 | 7 | 8 | 8 |
| 全部来源 | 知乎搜索 | 知乎搜索 | 知乎搜索 | 知乎搜索 |
| 热榜纳入 | 0 | 0 | 0 | 0 |
| 角色未判断 | 9/18 | 12/19 | 7/18 | 14/19 |
| 营销标记（纳入中） | 3 | 0 | 7 | 1 |
| 编码/条目均值 | 2.9 | 3.7 | 5.2 | 2.7 |
| 最早纳入日期 | 2019-07 | 2026-01 | 2022-10 | 2026-06 |
| 中位赞同 | 1 | 1 | 1.5 | 1 |
| 摘录平均长度 | 473 字 | 476 字 | 470 字 | 467 字 |

可读出的结论：

1. **热榜在示例中没有贡献**：扫描 30 条、纳入 0 条。热榜被写成方法的一部分，但实际只是「扫描后丢弃」。要么让它产生议程/趋势信号，要么不要把它当作证据来源。
2. **角色判断很弱**：9–14 条「未判断」。角色靠「我家/我买/从业」等词推断，无法可靠区分使用者、购买者、从业者。
3. **营销比例不低**：户外案例 7/18 条带营销标记。虽然发现会跳过「全部营销」的编码，但混合营销仍会计入计数。
4. **编码过度重叠**：户外案例平均每条 5.2 个编码，说明关键词规则区分度低；同一段文本可能同时命中多个主题。
5. **时间窗没有真正生效**：喂食器发现包含 2019/2021 年帖子，时间窗从 2024-11 开始；质量视图只标记，不剔除，也不做敏感性分析。
6. **摘录被截断**：平均 470 字，接近 480 字上限；编码基于截断文本，可能漏掉上下文/否定/结论。
7. **中位赞同只有 1**：样本不是「高赞共识」，而是搜索排序的混合内容；这其实比「只看高赞」更接近真实讨论，但需要说明抽样逻辑。
8. **单一平台、单一方法**：所有结论都受知乎用户结构、话题分布、搜索排序影响；没有第二个来源做交叉验证。

这些不是「产品 bug」，而是**方法边界**；专业团队会把它们写进 limitations，并在下一步用其他方法补上。

## 10. 不同用户的需求达成度

| 用户/场景 | 专业需求 | 知研台达成度 | 说明 |
|---|---|---|---|
| 产品经理，早期需求探索 | 语言、场景、失败模式、反对意见 | **60–70%** | 最快、最可审计的公开社区证据入口；不能单独支撑优先级 |
| 用户研究员 | 二手研究、访谈前假设、证据库 | **50%** | 适合 pre-interview；不能替代访谈/可用性；缺 repo |
| 市场/战略 | 规模、细分、定价、竞争 | **15–20%** | 缺量化与市场模型；只能做定性输入 |
| 出海团队 | 目标市场用户/渠道/合规 | **10–15%** | 中文知乎与北美市场不匹配；需海外数据 |
| B2B 产品/销售 | 采购委员会、win/loss、账户 | **10–15%** | 公开个人发帖≠企业采购；缺内部数据 |
| 设计师 | 可用性、任务流程 | **5–10%** | 无可用性测试/行为数据 |
| 创始人/小团队 | 快速第一轮证据、避免拍脑袋 | **65–75%** | 速度与边界诚实是优势；但要明确「假设生成」定位 |

## 11. 建议路线图

### P0（1–2 周，能在当前黑客松产品内完成）

1. **研究简报升级**：决策人、截止时间、决策标准、成功指标、约束、四类风险（价值/可用性/可行性/商业可行性）。
2. **RQ/假设/反证**：每个 RQ 写假设与「什么结果会让我们改变结论」；把场景映射到 RQ。
3. **方法适用性声明**：这份研究用什么方法、能回答什么、不能回答什么、需要哪些补充方法。
4. **抽样计划**：目标样本量、配额（角色/场景/时间）、饱和标准、非概率声明、敏感性分析（去掉营销/过时/单一来源后是否仍成立）。
5. **披露块（AAPOR-lite）**：数据来源、总体、抽样、日期、n、编码方式、AI 用途与人工监督、局限性。
6. **洞察层**：在「发现」之后增加「含义（so what）→ 建议 → 置信度 → 下一步实验」，允许人编辑，不由模型自动生成。
7. **反证与负案例**：在质检页增加「与结论相反的证据」「未覆盖/被忽略的声音」。
8. **决策 log**：记录决策、采纳/不采纳、后续验证计划。

### P1（1–2 个月）

1. **多源接入**：App Store/Amazon/小红书/抖音/客服工单/销售通话/竞品页面，统一 provenance 与三角验证矩阵。
2. **LLM 辅助编码 + 人工复核**：先做错误分析，代码断言优先，LLM-as-judge 只用于语义判断；报告 Cohen's kappa / 人工复核比例。
3. **研究资产库**：Postgres/Supabase，标签、全文检索、复用、权限、保留期限；替代 localStorage。
4. **量化模块**：问卷、MaxDiff、conjoint、价格测试、TAM/SAM/SOM 计算器；或与 Qualtrics/Sawtooth 集成。
5. **竞争/B2B 模块**：竞品集、定价拆解、win/loss、采购委员会、账户分层。
6. **协作**：评论、评审、@、版本、审批、导出到飞书/Notion/Slack。

### P2（一个季度以上）

1. 一手研究运营：招募、访谈、可用性测试、实验、面板。
2. 纵向研究：研究资产复用、趋势对比、决策结果追踪。
3. 企业治理：SSO/OAuth、权限、审计、数据保留、合规。
4. 评测体系：golden dataset、错误分类、baseline、回归测试、人工校准。

### 优先级判断

| 动作 | 对专业度影响 | 对演示影响 | 成本 |
|---|---|---|---|
| P0-1/2/3/4/5 | 高 | 中 | 低 |
| P0-6/7/8 | 高 | 高 | 低 |
| P1-2 编码信度 | 高 | 中 | 中 |
| P1-1 多源 | 很高 | 高 | 高 |
| P1-3 资产库 | 高 | 中 | 中 |
| P1-4 量化 | 很高 | 中 | 很高 |
| P2 一手/治理 | 高 | 低 | 很高 |

## 12. 定位建议

**不建议**继续用「AI-native research execution platform / 产品与市场研究平台」这种大词。专业评审会立刻问：市场模型在哪？抽样代表性在哪？竞争情报在哪？

**建议定位**：

> **知研台：面向产研团队的公开社区证据工作台。**
> 先把一个决策变成可核对的研究设计，用知乎等公开社区的真实表达建立样本、编码、质检，交付一份标明边界的早期发现简报；需要市场/定价/竞争结论时，明确进入下一层方法。

这个定位的好处：

- 与现有能力完全一致，不夸大；
- 把「诚实边界」从缺点变成差异化；
- 给后续多源、量化、竞争模块留出清晰升级路径；
- 对评委/用户都容易解释「什么时候该用、什么时候不该用」。

对黑客松而言，最有说服力的不是「我们什么都能做」，而是「我们知道自己只能做什么，并且把这条链路做到可审计」。
