# 知研台 Zhiyan V2 产品说明计划书

知乎黑客松 S3 · 湾区共创季 · 主报 AI×出海 · 能力底色 AI×知识与探索

## 一句话

**面向全球 OPC 的知乎研究台：把英文产品决策变成中文研究计划、适应性知乎检索和一份可复核的双语决策简报。**

> A research team for global builders, built on real Zhihu conversations.

## 为什么做

AI 正在把「把产品做出来」的成本打下来，判断「什么值得做」反而成为新的瓶颈。一人公司和小团队没有专职研究团队，却要在开发前理解真实用户、发现未知问题、检查产品假设。中文知乎有大量真实讨论，但海外团队很难系统使用。

V2 不做一个更大的研究平台，而是把现有能力串成一条可演示、可检查的主线：

> 英文产品决策 → 中文研究计划 → 适应性知乎检索 → 可接管证据分析 → 双语决策简报 → 下一步验证。

## 三层出海

1. **产品出海**：英文优先，面向全球用户。
2. **知识出海**：把知乎中文公开讨论转化为全球团队可理解、可复核的英文研究证据。
3. **决策出海/入华**：海外团队进入中国前理解本地用户；全球 OPC 获得中文用户研究能力。

## 与通用 AI 的差别

通用 AI 可以读到部分公开网页，也可能搜到部分知乎内容。知研台的差别不是模型会不会搜索，而是系统是否真的执行研究：

- 查询有预算、轮次和目的；
- 新词必须来自真实样本，并保留来源样本与原句；
- 覆盖、反例和扩展查询写入计划新版本；
- 样本可被用户修改，发现和双语报告同步重算；
- 结论可回到中文原话、英文翻译和知乎原文链接。

## P0 用户流程

1. 用户用英文/中文提交产品决策。
2. 系统生成结构化 Brief 与中文研究计划。
3. 方法适用闸门判断：适合知乎探索 / 需要其他数据 / 不能单独证明。
4. 用户确认计划；确认前不调用知乎。
5. 适应性检索：4–6 个种子查询，最多 2 轮扩展，单次研究默认不超过 12 次查询、60 条候选。
6. 从真实样本提取新词，每条带来源样本、原句、覆盖缺口和下一条查询。
7. LLM 辅助语义编码 + 确定性计数 + 人工修改；主动反例检索或披露反例缺口。
8. 生成六类发现：人群与场景、任务与痛点、替代方案、选择理由、分歧与反例、未知问题与证据缺口。
9. 交付中英一致的 Decision Memo、完整报告、证据附录和下一步访谈提纲。
10. 用户可搁置样本、修改编码与主题；分析、计数和双语报告即时重算。

## 主案例

> 一个海外 OPC 准备为中国自由职业者开发 AI 合同与回款工具，希望理解报价、反复改需求、验收和拖款问题，再决定是否投入开发。

真实缓存结果：12 次查询、3 轮、60 条候选、47 条纳入、12 个有来源的新词、8 条六类发现。系统发现了「款清交源文件」「带水印的低清预览版」「视为验收条款」「需求变更书面确认」「资金托管」「正式书面催告」等原生表达，并保留了反例与证据缺口。

- [x] 方法适用闸门与报告措辞约束
- [x] 研究计划确认与版本更新
- [x] 至少一轮由样本证据触发的真实查询扩展
- [x] 查询目的、词汇来源、覆盖缺口可视化
- [x] 主动反例检索与反例缺口披露
- [x] LLM 辅助语义编码 + 确定性计数 + 人工修改
- [x] 每条关键发现可回到中文原话、英文翻译和知乎原文
- [x] 样本搁置后，分析和两个语言版本同步更新
- [x] 双语 Decision Memo 与下一步验证

## 明确不做

TAM/市场规模/购买率预测；Conjoint、MaxDiff 等定量模块；合成用户冒充真实证据；多平台数据接入；自动招募、AI 访谈、问卷投放；企业 SSO、复杂权限、多 Agent 聊天界面；自动向知乎发布内容。

## 比赛评分对应

| 维度 | 权重 | 证据 |
|---|---:|---|
| AI 场景价值 | 40% | 全球 OPC 的真实产品决策；知乎知识出海；从真实讨论发现用户不知道要搜什么；报告落到下一步验证 |
| 创新度 | 25% | 方法闸门 + 适应性词汇发现 + 可接管证据 + 双语 Decision Memo；不是通用 AI 搜索 |
| 完成度 | 25% | 计划 → 检索 → 编码 → 发现 → 质检 → 双语交付完整可跑；缓存离线可演示；测试/构建/验收脚本通过 |
| 产品体验与设计感 | 10% | 知乎式蓝白信息流、中文/英文切换、刘看山 IP、证据可下钻、响应式、可导出 |

## 演示动线（5 分钟）

1. 讲问题：AI 让产品更容易做出来，但 OPC 仍靠猜决定做什么。
2. 英文输入主案例，展示中文研究计划与「知乎不能证明付费率」的闸门。
3. 打开探索：展示从样本长出的新词、来源原句、下一轮查询和反例检索。
4. 打开样本：搁置一条营销/不可靠样本，发现和双语报告即时变化。
5. 打开交付：英文 Decision Memo、中文原话、原文链接和下一步访谈证伪条件。
6. 收尾：知研台让知乎内容成为中文知识出海和机构研究服务的新入口。

## 评委问答口径

**直接让 ChatGPT 搜知乎不也行？**
它可以读到部分公开网页，但不会天然形成有预算、有覆盖目标、有反例、有纳入排除和可重算证据链的研究过程。差异不是模型会不会搜索，而是系统是否真的执行研究。

**这不就是翻译和总结吗？**
翻译只存在于交付层。核心过程是把英文决策拆成中文查询，从真实讨论发现新词，再用新词补齐覆盖和反例，最后让用户修改证据并重算结论。

**这些讨论能代表中国市场吗？**
不能，所以系统把知乎限定为定性探索证据，并在方法闸门和交付中阻止统计化结论。它帮助决定下一步验证什么，不代替市场统计。

**知乎自己做怎么办？**
知研台是在知乎官方能力上验证新的应用和商业化场景，目标是成为知乎知识出海和机构研究服务的应用样板，而不是绕过平台抓取内容。
