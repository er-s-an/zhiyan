# 知研台 Zhiyan 产品说明计划书

知乎黑客松 S3 · 湾区共创季 · AI × 知识与探索

知研台是一个**研究执行工作台**。用户交来的是一句商业决策，不是一个搜索词。系统先把决策编译成一份可编辑的研究设计；等人确认之后，才对知乎做搜索、热榜核对和直答补漏，建立样本、编码、质检，最后交付一份写明边界的团队研究简报。知乎是数据基础和方法来源，不是产品本身。

## 一句话

**把一句业务问题，跑成一份可核对的知乎研究。**

## 要解决的问题

产研团队每天都要做小决策：这个功能要不要做、这句宣称能不能用、这批选品先上哪个、知识库值不值得投入。他们真正缺的不是更多帖子，而是一套能开会、能交接的方法：

- 知乎上有大量真实使用经历，但搜索框只给链接，不给研究；
- 一篇高赞回答容易被当成购买意愿，一条营销帖会混进真实使用；
- 旧帖会被当成现在的产品事实，样本外的东西被顺手写进结论；
- 团队想要「用户原声」，却经常拿到一堆无法溯源的摘要。

知研台把这条路径固定下来：**先确认方法，再动数据；每条结论有样本；每个边界都写出来。**

## 目标用户与真实场景

| 用户 | 会前要回答的问题 | 示例案例 |
| --- | --- | --- |
| 硬件产品团队 | 多猫喂食器哪些功能是刚需，哪些宣称站不住 | 多猫智能喂食器 |
| 效率工具产品经理 | AI 会议纪要哪些能力真会被每天使用 | AI 会议纪要 |
| 出海品牌 / 独立站 | 北美户外储能用户为哪些场景买单 | 户外储能出海 |
| 平台与效能团队 | 50 人产研团队为什么用不起 AI 知识库 | AI 知识库落地 |

典型使用时点是评审会、立项会、用户访谈前。用户需要的是**一份带出处、能解释方法、能说明局限的简报**，不是一篇看起来很像报告的生成文本。

## 产品闭环

1. **研究简报**：一句中文业务问题，中英文都可以。生成研究设计时不调用任何知乎接口。
2. **研究设计**：决策、对象、阶段、能回答 / 不能回答、场景、人群、时间窗、纳入与排除、停止规则、中文检索词。全部可编辑；两条方法限度锁死，删不掉。
3. **确认门**：只有研究员点下「确认设计并开始检索」，服务端才发起知乎调用。未确认的请求直接拒绝。
4. **检索与样本**：知乎搜索是承重的，热榜用于核对当天站内议程，直答只根据已检索标题提示可能漏掉的场景。每条来源保留纳入理由、查询、日期、场景、营销 / 重复 / 二手标记。
5. **分析与质检**：可见关键词编码，主题计数只属于本样本。至少两条纳入条目带同一编码，才形成一条发现。质检标出单一来源、未覆盖场景、样本内冲突、过时内容和超出证据的推断。
6. **交付**：中文研究简报、主题分布、中英对照摘录、结论边界、下一步方法、检索记录。可复制 Markdown、下载 `.md`、打印为 PDF。

## 界面与体验

界面重做为**知乎蓝白主题的工作台**，面向产研用户的日常习惯：

- **左导航 + 顶部面包屑 + 内容卡片**：工作台、新建研究、当前研究、示例库、产品说明五个入口，路径稳定，移动端自动收成顶部导航。
- **中文优先**：按钮、状态、空态、错误与报告正文全部中文；英文只保留在双语摘录和必要的方法术语里。
- **方法前置**：设计页右侧常驻「执行前检查」，把 0 次调用、检索词数量、将发生的调用写清楚，再给确认按钮。
- **样本可操作**：左列表右详情，筛选、搜索、展开摘录、点击编码、改场景和角色，改完立即重算。
- **诚实边界第一屏**：质检页首屏是「可以支持 / 不能证明」，交付页带着同一条边界。
- **刘看山 IP**：官方三视图素材用于品牌位、空态和提示位，不改变角色比例，不用 emoji 充当图标。
- **示例库**：四个已经跑完并缓存的真实案例，评委可以离线走完整条闭环；也可以选案例重新跑一遍。

## 核心创新

1. **方法编译器**：把商业决策收成可执行的研究设计，而不是把问题丢给搜索或聊天模型。喂食器、会议纪要、户外储能、知识库四类问题各自带有场景、编码本、人群和停止规则。
2. **确认门**：确认是产品的一部分，不是 UI 装饰。检索路由会重新校验设计，拒绝设计外的查询，避免服务端密钥变成开放搜索代理。
3. **样本是唯一事实源**：分析、质检和报告都是投影。排除、恢复或改标签之后，计数和报告一起重算，不另存一份会漂移的结论。
4. **锁定的诚实边界**：「现有知乎讨论不能证明购买意愿」「不能把一条宣称验证成足以支撑购买」两条写在设计里，删不掉。报告必须同时写出能支持与不能证明的东西。
5. **可演示的完整案例库**：四个案例使用真实知乎检索快照缓存，演示不依赖现场网络和额度；同时保留「重新研究」路径，评委可以现场验证闭环。

## 技术实现

- **前端**：Next.js 15 App Router、React 19、TypeScript、纯 CSS 设计令牌；`lucide-react` 图标；无 UI 框架依赖。
- **领域层**：严格类型的 `compile` / `sample` / `project` 领域函数；研究设计与投影均由确定性代码生成，模型不参与发现、计数和边界判断。
- **服务端**：Next.js Route Handlers；知乎开放平台 Access Secret 只存在服务端 `.env.local`，不进前端响应、日志或仓库。
- **知乎能力**：`zhihu_search`（每条计划查询一次）、`hot_list`（核对当天议程）、`zhida`（只做补漏提示，不进入发现）。不做发帖、不做批量操作。
- **大模型**：DeepSeek V4.1 Flash（OpenAI 兼容接口，经 OpenCode Go）只负责把中文摘录译成英文；失败时保留中文证据并明确标注，不影响分析和报告。
- **存储**：浏览器 localStorage 保存当前设计与样本；示例快照以 JSON 放在仓库内，由 `/api/demos` 读取。没有为竞赛绑定付费数据库。
- **可靠性**：每次检索都带确认和设计校验；搜索全部失败或热榜失败时不生成研究，不用直答顶替结论；示例库保证演示可重复。

## 和知乎生态的契合

- 用**真实问答内容**取样，用**热榜**核对站内议程，用**直答**补漏。三者一起，才算用了知乎生态，而不是让一个聊天模型转述知乎。
- 不生产垃圾回答，不批量发帖，不把答主拖进未经授权的接触。
- 高赞表示其他读者觉得有用或同意，**不是购买者的概率样本**；营销账号和真实照料者会出现在同一批结果里；回答常常混着亲历和听说。这些话写在交付的「中国互联网语境」里。
- 中文摘录是证据，英文是给全球团队的翻译。产品尊重知乎的中文社区语境。
- 使用刘看山官方 IP 三视图素材，保持角色形象完整，不二次创作变形。

## 演示动线（5 分钟）

1. 首页用一句「多猫家庭智能喂食器」简报生成设计，指出 **0 次知乎调用**。
2. 在设计页讲确认门、锁定的两条限度和停止规则，然后确认（或直接进示例库）。
3. 打开示例库的第一个案例，进「协议」看实际执行的检索记录和直答补漏。
4. 进「样本」：点一条来源，展示纳入理由、中文摘录和编码；搁置一条，看分析计数变化。
5. 进「质检」：首屏「可以支持 / 不能证明」，再讲覆盖与缺失。
6. 进「交付」：复制 Markdown 或下载 `.md`，以「下一步换方法」收尾。

现场更稳的做法：示例库四个案例全部使用缓存快照，点开即用；需要证明真实调用时，用「重新研究」跑任意一个案例。

## 评分维度对应

| 维度 | 权重 | 对应证据 |
| --- | ---: | --- |
| AI 场景价值 | 40% | 产研日常决策场景；四个真实案例；知乎内容成为可交接的方法资产，而不是一次性答案 |
| 创新度 | 25% | 方法编译 + 确认门 + 样本投影 + 锁定边界；把「研究流程」产品化，而不是多一个聊天窗口 |
| 完成度 | 25% | 设计 → 检索 → 样本 → 分析 → 质检 → 交付完整可跑；示例库离线可演示；错误与降级有真实提示 |
| 产品体验与设计感 | 10% | 知乎蓝白工作台、中文优先、刘看山 IP、响应式、可导出、键盘焦点与对比度 |

## 这次不做的事

- 不做付费访谈撮合，不邀请答主进入未经授权的研究；
- 不把一次样本悄悄变成训练集；
- 不做市场规模和购买意愿的假证明；
- 不接入 Reddit 等非赞助方数据源；
- 不做发帖、评论或批量请求。

以后可以做的方向：研究资产库（带授权与保留期限）、知乎 OAuth 登录、团队协作与评论、更多行业场景包、报告分享链接。
